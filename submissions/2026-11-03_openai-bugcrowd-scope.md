# OpenAI Security Bug Bounty (Bugcrowd) — scope & rules brief

Scope-and-rules pass only, 2026-11-03. Sources: the public program page https://bugcrowd.com/openai (full text read 2026-11-03 ~12:22 UTC) + OpenAI's reward announcement coverage. **No testing, scanning, or probing of any OpenAI system was done for this brief.** Findings, when hunting starts, get packed for Claude's review under the submissions skill before anything is submitted.

## Program status
- **Live and public.** The program page is publicly readable without an invite. Running since April 2023 on Bugcrowd.
- A separate **Safety Bug Bounty** also exists on Bugcrowd for safety/abuse issues (model-behavior reports belong there, NOT here — see out-of-scope). Reports can be moved between the two programs.
- Live-hunting event noted on the page: OpenAI's team runs a live bug bounty at Prompt2Pwn (NahamCon), Oakland, Nov 20–21, 2026.
- Page readability note: the brief/scope/rules text rendered fully in a text crawl. The per-severity reward table widget did NOT render as text — payout figures below are from OpenAI's announcement, cross-checked against two write-ups that read the Bugcrowd page on 2026-11-03.

## Payout (as raised 2026-11-02 — verify the live table on the page before estimating any single report)
- **Critical in a core product (ChatGPT, Codex, API Platform): up to $30,000 base.**
- **Exceptional critical findings: up to $100,000 before bonuses; up to ~$172,000 with bonuses.**
- Midpoints of the medium/high/critical ranges "more than quadrupled on average" (OpenAI's wording).
- Bonuses stack multiplicatively on the base: report-quality bonus up to **1.15×** (reliable proof of concept), priority-campaign bonus up to **1.30×** (newly launched features), five-tier loyalty bonus **+5% to +15%** for repeat researchers.
- Retroactive: unawarded reports get the new ranges; awards from the 30 days before the announcement are topped up.
- Historical context: the range was $200–$20,000 from 2023; the exceptional-critical ceiling has been $100,000 since March 2025. Real awards often land well below ceilings (a P1 was paid $5,000 in Oct 2026).
- P5 (Informational) findings: submittable but **no monetary reward** and no committed response timeline. Corporate-info documents typically rate P4/P5 = usually no money unless particularly sensitive.
- Severity is set by demonstrated impact, not bug type — e.g. UI-only findings in Codex's browser/extension are P5 unless they demonstrate P1 impact.
- No reimbursement for upgrades or purchases made on your account.

## IN-SCOPE targets (exact list from the program page)
1. **OpenAI API** — `https://api.openai.com` (`api.openai.com`), plus public cloud resources/infrastructure serving the API (e.g. Azure storage blobs, Azure VMs). Interested in: XSS, CSRF, SQLi, authn/authz issues, data exposure, payment issues, ways to run queries on pre-release or private models. Also accepted: demonstrated access to unreleased/private models (send requests + receive output), severity by model sensitivity. **Exception carved out:** methods to bypass Cloudflare on api.openai.com are listed as out-of-scope examples (see below) even though "bypass Cloudflare by reaching unprotected endpoints" appears as an interest under ChatGPT — treat the API-Cloudflare bypass as out, and ask Bugcrowd support before relying on the ChatGPT-side line.
2. **ChatGPT** — `https://chat.openai.com`, incl. ChatGPT Plus, logins, subscriptions, payments. Include the conversation ID (URL) when a conversation demonstrates the issue.
3. **ChatGPT Plugins** — same host. OpenAI-created plugins (Browsing, Code Interpreter) and **plugins you create yourself** + the plugin creation system (browser-crash outputs, credential security, OAuth, SSRF, making the plugin service call unrelated domains vs. the manifest origin). **Never test other people's plugins.**
4. **Dots** — `https://chatgpt.com/dots/` (marked New).
5. **Codex surfaces** (submit browser/extension issues under the **Codex Desktop** target): Codex CLI, web, and desktop; the built-in browser in the ChatGPT desktop app; the ChatGPT Chrome extension (ID `hehggadaopoacecdllhhajmbjkdcmajg`); and OpenAI-controlled software connecting them. In scope = defects where a **less-privileged attacker bypasses an enforced security restriction**: sandbox escape (filesystem/network/process-OS boundaries), in-app-browser/extension compromise, cross-origin/cross-context access via an implementation flaw, sensitive browser-data exposure, file/download/network boundary violations, bypass/forgery/replay/mis-binding of required approvals and other enforced controls, bypassing admin-enforced restrictions. Reports must reproduce on a **current, supported release in a supported configuration**; `/experimental` features are not reward-eligible.
6. **openai.com + `*.openai.com`** — the website, Developer Documentation, Developer Playground (`https://platform.openai.com/playground`), any other internet-facing OpenAI-operated infrastructure not in another target, and other public cloud resources OpenAI operates. (Unused subdomain takeovers are in scope.)
7. **Research-org sites** — `https://openai.org` and `*.openai.org` (websites/services/APIs of the OpenAI research organization).
8. **Third-party exposure of OpenAI corporate information** ("Third Party Targets") — confidential OpenAI info exposed via vendors (examples listed: Google Workspace; Asana/Trello/Jira/Monday; Notion/Confluence/Evernote; Intercom/Hubspot/Zendesk; Stripe/Airebase/Navan; Mode/ChartHop/Looker). **Observation only: NO security testing against those companies** — searching for exposed OpenAI information within all laws and the vendors' ToS only. Submissions must detail the discovery process. Multiple documents sharing a root cause may pay at higher rates.
9. **Leaked OpenAI API keys** ("OpenAI API Keys" target) — **special channel:** do NOT submit keys through Bugcrowd (marked out-of-scope + point deduction). Report via the OpenAI API Key Bug Bounty Submission Form (Google Form linked on the page). Valid keys carry `sk-` or `sess-` prefixes; submit in bulk, first reporter only, monthly bonus to the most impactful submission. Don't create keys to submit, don't resubmit the same keys, don't post/share keys anywhere.

## OUT-OF-SCOPE (the guardrail list — full, from the page)
**Model issues — strictly out of scope here, never rewarded in this program:**
- Model safety/content issues of any kind; prompt injection, jailbreaks, hallucinations, misleading model output; "weird model behavior" from special/bugged tokens; overlong-input outputs that look like other people's answers (a known hallucination form).
- Prompt injection counts ONLY when it exploits a **separate, demonstrable security-boundary flaw** in an in-scope product/integration; application-layer chains showing low-interaction transfer of user data to a third party inside OpenAI's apps are of interest, but model-internal mitigations are not accepted (model-behavior feedback goes to the model feedback form / the Safety program). An agent misusing access or approvals it legitimately has = out of scope, even if data leaks.
- Sandboxed code execution inside the ChatGPT code-interpreter feature; "you can send shell commands to the Code Interpreter VM" (expected functionality).

**Attack classes:**
- Anything that degrades/disrupts services or user experience: DoS, brute force (**including brute-forcing the APIs**), password spraying, spam, **fuzzing — unless specifically authorized by OpenAI's security team**.
- Destroying/corrupting data that isn't yours; attacks from stolen/leaked credentials; accessing data that isn't yours beyond the minimum needed to demonstrate the bug.
- Physical attacks, social engineering, phishing against OpenAI personnel/offices/networks/property.
- Anything on systems not explicitly listed as in-scope.
- Email-server/protocol issues (SPF/DMARC/DKIM/spam).
- SSL/TLS cipher reports or missing HTTP headers (e.g. no HSTS) without a working PoC; clickjacking; server error messages without an exploit; server version strings; issues affecting only old/EOL browsers/plugins; verification tokens in `./well-known/ai-plugin.json`; dependency-confusion via posting internal package names to public repos; discovery of names/references to unreleased products/features.

**Named known-issues / expected behavior (do not report):**
- Domains CNAME'd to Stripe (e.g. `pay.openai.com`) → report to Stripe's program. Domains CNAME'd to other third-party providers (e.g. `community.openai.com`) are out (unused subdomain takeovers still in).
- Password change may not invalidate all tokens/keys · adding users to your org without their permission · account deletion without password · API keys have broad permissions · making more API keys than the cap · cookies transferable between browsers · ChatGPT displays images from other domains (exception: where loading transmits sensitive user data to a third party without consent) · OpenGraph preview behavior · sharing playground presets by link · changing the email sent to Intercom · billing lag · creating accounts via online SMS services (without a different, specific issue).
- Rate-limit/quota findings unless a **complete, meaningful bypass at scale**: they reward bypasses enabling sustained usage at significant scale (hundreds of requests beyond limits); temporarily exceeding RPM/TPM limits or the hard spending cap is explicitly out.
- Bypassing IP blocks/geoblocks via VPN · bypassing Cloudflare on api.openai.com · bypassing the "ChatGPT is at capacity" page · emulating a browser to bypass CAPTCHAs.
- Websites not owned/operated by OpenAI, including `ai.com` and `open.ai`; phishing sites, ChatGPT proxies, Discord bots and other "free" access sites; third-party browser plugins that modify ChatGPT.
- Vulnerabilities in most dormant OpenAI open-source projects (reports welcome, rewards typically only for demonstrated impact in actively maintained projects).
- Issues needing excessive user cooperation / unlikely social engineering (self-XSS via debug pane, disabling browser security features, loading malicious external content, out-of-band exfiltration setups).
- Codex-specific: normal browsing, valid cross-origin requests, declared extension permissions, authorized connected profiles, intentionally shared browser state, anything the active configuration allows; social engineering/persuasion without an implementation flaw; user-installed malware / already-compromised device / root or admin access / unrestricted code running with the user's authority (unless a separate enforced boundary is crossed); third-party browser/site/extension/dependency issues without an independent OpenAI-specific flaw; performance issues, unsupported/obsolete versions, speculative missing-hardening claims, non-security bugs; DoS requiring sustained/large-scale traffic; features not available via a current supported release/rollout/OpenAI-identified testing path; sandbox-escape reports requiring bespoke malicious project folders (exceptions: behavior occurring before the project-trust dialog, and bugs triggerable through common interactions like cloning a repo); **upstream Chromium/Chrome vulnerabilities that reproduce in unmodified upstream Chrome** → Google's Chrome VRP (narrow exception for previously disclosed Chromium bugs in the Codex-bundled browser when 7+ days past Google's fix, no fixed Codex release exists, and a High/Critical Codex boundary violation is demonstrated in the latest supported release).

## Rules of engagement
- **Automation verdict: NOT expressly banned, but sharply limited.** The page never bans scanners outright; it warns: "Automated vulnerability scanners may trigger these outcomes" (rate limiting, blocking, banning), blocks are never manually removed, and bans get only limited discretionary un-banning via support@bugcrowd.com (never for content violations; repeated ban evasion = removal from the program). **Fuzzing, brute force, password spraying, spam and DoS are out of scope unless OpenAI's security team specifically authorizes them** — so any automated testing beyond gentle, low-volume requests needs written authorization first. Authorized testing does NOT exempt you from OpenAI's Terms of Service.
- **Rate limits:** none numerically published on the page; the practical limit is "don't get blocked, and if blocked, wait it out."
- **Testing accounts:** your personal account, or an additional testing account registered with your **@bugcrowdninja.com** address — preferred, not mandatory. Multiple accounts / mass key generation violates OpenAI's terms (suspension risk; also stated in the API-key initiative rules).
- **Identification headers:** no special X-header or user-agent requirement is stated on the page. (Identify via the bugcrowdninja account instead.) If unsure whether planned research fits the policy: contact support@bugcrowd.com BEFORE proceeding — the page explicitly invites this.
- **Testing safely:** test only accounts/devices/profiles/websites/data you own or are authorized to use; use your own websites and ordinary supported workflows to demonstrate a boundary violation; **stop once the issue is demonstrated**; never access another person's data, make real purchases, take destructive actions, disrupt services, or attack OpenAI personnel or unrelated third parties.
- **Report contents (required shape):** attacker's starting authority, the applicable security restriction, the protected resource/action, the concrete unauthorized outcome; affected product + version, OS, active configuration, relevant permissions/approvals, reproduction steps. ChatGPT findings: include the conversation ID. Browser/extension findings: file under the **Codex Desktop** target.
- **Safe harbor (verbatim substance):** "OpenAI will not threaten or bring any legal action against anyone who makes a good faith effort to comply with this bug bounty policy," including DMCA circumvention claims for in-policy research; compliant research is considered "authorized" under the CFAA and similar state laws, and conflicting Terms of Use / Usage Policy restrictions are waived for the limited purpose of the research. Third-party systems: OpenAI cannot authorize research on them and can't guarantee they won't act, but will state your actions were policy-compliant if they do. You must still comply with all applicable laws.
- **Disclosure:** the engagement follows Bugcrowd's standard disclosure terms; public disclosure of a finding requires explicitly selecting the disclosure-request option on the submission (see Bugcrowd's Public Disclosure Policy). OpenAI also acts as a CVE Numbering Authority with its own CVE assignment/coordination policy.
- **AI-assisted research policy:** **not stated on the program page** — no clause grants or bans AI assistance for the security program (the AI-related clauses all concern model behavior being out of scope). Under the submissions skill's rule (skip programs that ban AI-assisted entries), nothing found bans it; flag as "not mentioned" and re-check at first submission. Note the separate Safety program is where prompt-injection/agent-misuse findings go.

## Hunt plan (later phase — methods the rules allow only)
1. **Start with your own accounts and surfaces you fully control:** ChatGPT (own account) and your own self-created plugins — the plugin creation system is explicitly in scope (OAuth, SSRF, credential handling, manifest-origin call behavior) and testable entirely against your own plugins and your own server endpoints. Never touch other users' plugins.
2. **Codex desktop/CLI locally:** install current supported releases, test sandbox/approval boundaries against your own files, repos, and websites (project-trust dialog timing, approval replay/mis-binding, browser cross-origin enforcement) — all local, all your own data, reproducible configs only.
3. **API platform with your own keys/org:** authorization boundaries between your own projects/organizations and API-key permission behavior on platform.openai.com + api.openai.com, manually, low volume — no fuzzing, no brute force, no scanner sweeps without written authorization from OpenAI's security team (ask via support@bugcrowd.com first if a method is borderline).
4. **Passive corporate-exposure lane:** public-web searching for exposed OpenAI corporate documents in the named vendor categories (observation only; zero testing of the vendors), plus the leaked-API-key initiative via its separate form (bulk, first-reporter, never post keys).
5. **Explicitly skip:** anything model-behavior (route to the Safety program instead), Cloudflare-bypass on the API, rate-limit minutiae, header/cipher/version-string reports, and every named known-issue above.
