Project Description: Zcash's adoption story is told with numbers the ecosystem cannot currently reproduce: a shielded adoption percentage whose derivation is not published end-to-end, wallet UX claims (shielding speed, sync reliability) that are not measured on real devices under controlled conditions, and ecosystem maps that age quickly and are not maintained as data. This project produces the missing measurement layer as public goods: 1. **Shielded adoption, reproducibly.** A documented, scripted derivation of the shielded pool / adoption figures from public chain data, published with the exact code, parameters, and block heights used, so the number can be re-derived or challenged by anyone. 2. **Live wallet testing on real devices.** A controlled test protocol run on physical devices with real (small) funds across the maintained shielded wallets: time-to-first-shielded-transaction, proving time, sync behavior from cold start and from restore, and error/failure rates — recorded per wallet, per device class, per network condition, and published as raw data. 3. **Ecosystem mapping as data.** An updated map of the Zcash privacy ecosystem (wallets, infrastructure, integrations, tooling) published as a structured, versioned dataset rather than a one-off graphic. This is deliberately not another analytics dashboard: the deliverables are the underlying datasets and methods that dashboards, researchers, and the committee itself can build on and audit.
Proposed Problem: 1. **Unreproducible headline figures.** The shielded adoption figure cited across the ecosystem has no published, reproducible derivation; when the methodology is not public, the figure cannot be verified, corrected, or tracked consistently over time. 2. **Unmeasured wallet reality.** Shielded UX is the adoption bottleneck, yet time-to-first-shielded-transaction, proving time, sync behavior, and error rates are not systematically measured on real devices with real funds under stated conditions. 3. **Stale ecosystem maps.** Ecosystem mappings are produced as one-off documents; there is no maintained, structured dataset of the privacy ecosystem's components and their status.
Proposed Solution: Apply a reproducible-measurement protocol to all three gaps: fixed methodology published in advance, scripted data collection, raw data released alongside every derived figure, and datasets versioned so later editions are diffs, not restarts. Each deliverable ships as (a) the dataset (CC BY 4.0), (b) the methodology document, and (c) the collection/derivation code (open source), so the work is auditable and reusable by ZecHub, researchers, and wallet teams.
Solution Format: Open datasets (CSV/JSON) under CC BY 4.0, versioned releases · Methodology and findings reports (Markdown/PDF) · Open-source collection and derivation code with a `CONTRIBUTING.md` · Forum thread updates (required monthly, and at each milestone)
Dependencies: Public Zcash chain data and public light-wallet infrastructure; maintained shielded wallets as test subjects. No privileged access, no third-party deliverables. Small amounts of real ZEC for live-device tests are covered in the budget.
Technical Approach: **Adoption derivation:** compute shielded pool balances and adoption ratios directly from chain data at stated block heights; publish the full script and parameters; cross-check against existing public trackers and document any discrepancies and their causes. **Wallet testing:** a fixed test script (fresh install → wallet creation/restore → first shielded transaction → repeat transactions) executed on physical devices; instrumented timing for proving and sync; errors logged verbatim; multiple runs per configuration; raw logs published with the dataset. **Ecosystem mapping:** structured census of wallets, infrastructure, integrations, and tooling with status fields, compiled from public sources and direct verification, released as a versioned dataset with a changelog.
