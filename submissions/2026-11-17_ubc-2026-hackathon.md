## Fields (exact text)
Project name: CapAgent — a capped USDC payments agent on Solana
Tagline: Give an AI agent a wallet it can't overspend — hard caps on every USDC payment, with a public audit log.
Main track: Agentic Payments and AI
Chain award: Best use of Solana
Bounties: None
Team members: John Tedesco (solo)
What did you build?: CapAgent is a Solana devnet USDC agent with hard spending caps. An AI agent pays per-use for data and API calls in USDC, but it can never exceed owner-set caps: $0.50 per call, $5.00 per day (rolling 24h), and $2.00 per vendor (rolling 24h). Every payment decision — approved, denied, or failed — is written to an append-only, SHA-256 hash-chained audit log that anyone can verify and export. It is a static web app with no backend: an ephemeral devnet wallet is generated in the browser, a cap-settings panel, a five-task agent run, a spending summary, and the audit log with a one-click chain verifier. It ships in two modes: a simulated ledger (default, works with zero funds) and live devnet mode that makes real SPL USDC transfers when the wallet is funded. Built fresh Nov 19–20, 2026, during the hackathon. Verified: 17/17 unit tests pass; a default agent run approves 4 tasks ($0.80) and denies the $1.20 deep market scan for exceeding the $0.50 per-call cap, with the audit chain verifying clean.
What problem does it solve?: Give an AI agent a wallet and it can spend without limit — runaway API bills, a compromised prompt draining funds, or one expensive call eating the budget. Existing agent wallets have no built-in spending discipline. CapAgent is the guardrail: the agent can only pay for what was pre-approved, inside caps the owner sets, and every decision is written to a verifiable public audit log, so overspending is impossible by construction and every payment is accountable after the fact.
How does it work?: The cap engine (src/caps.js, pure JavaScript, no Solana dependency) evaluates every payment before money moves: it denies any payment over the per-call cap, over the rolling-24h daily cap, or over the rolling-24h per-vendor cap, re-measuring spend from the audit log before each task so denials inside one run already reflect earlier approvals in that run. The audit log (src/audit.js) is append-only and hash-chained — each entry stores its SHA-256 hash linked to the previous entry, and Verify re-hashes the whole chain; any edit, deletion, or reorder fails verification. The agent loop (src/agent.js) runs a catalog of priced data tasks, requests one payment per task, and records APPROVED or DENIED with the reason. In live devnet mode, approved payments are real SPL USDC transfers from the ephemeral in-browser keypair (USDC devnet mint 4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDnc); in simulated mode the same flow is recorded as a clearly labeled simulated transfer. Balances are read live from Solana devnet.
What makes it unique?: The caps are enforced in code before any payment, not as a dashboard after the fact — a denied payment is a denial, not a notification. Three independent cap dimensions (per-call, rolling daily, per-vendor) cover the three ways an agent actually overspends. And the audit log is tamper-evident by construction (hash-chained), so the spending record itself is trustworthy without trusting the agent or the operator. The whole enforcement core is two pure-JS modules with zero Solana dependency, so it is unit-tested in plain Node (17/17 tests) and portable to any chain or payment rail.
What would you build next?: Real vendor payout wallets instead of deterministic demo addresses; a persistent, shareable audit log (public feed per agent); per-task approval policies (e.g. auto-approve under $0.10, require owner sign-off above); mainnet support behind the same cap engine; and an x402-style pay-per-call handshake so data vendors can quote a price and the agent pays it inside its caps automatically.
Technologies / sponsor tools used: JavaScript (ES modules, no framework), @solana/web3.js + @solana/spl-token (loaded from esm.sh in the browser), Solana devnet, USDC (devnet mint), SHA-256 hash-chained audit log, Node.js built-in test runner (node --test). No sponsor tools used. AI tools: built with Muse AI agent crew assistance; John Tedesco is the primary creator and directed the design (disclosed in the README).
